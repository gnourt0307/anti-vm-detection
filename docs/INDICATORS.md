# Indicator coverage and configuration boundaries

These are observations of exposed interfaces, not an undetectability score. A marker token or known OUI is heuristic evidence. Multiple APIs may reflect one underlying device. Hypervisor presence on a physical Windows 11 development host may come from Hyper-V/VBS; it does not by itself prove the host is a VMware guest.

Classification: **I** inspectable; **C** supported configuration exists for some behavior; **H** hypervisor/virtual-device controlled; **R** invasive or unsupported approaches are research-only; **P** can persist and cannot realistically be eliminated by this guest toolkit. All engine modules are read-only. A scan normally needs no administrator rights; device, SCM and WMI access policy may require elevation. Failed access is recorded. No scan requires reboot.

| A: CPU vendor, brand, features, hypervisor bit | CPUID 0, 1, 7.0, 0x80000000..04, invariant-TSC bit | I/H/P. Workstation processor count and cores/socket via UI; no automatic CPUID masks | Report raw registers; bit-clear is not proof of absence; features can legitimately differ from host |
| A: hypervisor vendor/leaves | Validate advertised 0x40000000 range; record up to first 17 leaves even if hypervisor bit is clear | I/H/P; leaf meaning vendor-specific | Compare raw leaves. No undocumented I/O backdoor probes; not all hypervisor namespaces are enumerated |
| A/K: topology/features | CPUID 0xB subleaves, Windows logical/core/package counts; Win32_Processor counts; AVX/XSAVE and AVX2/AVX feature consistency | I/H/C; configure supported vCPU topology on powered-off VM | Leaf 1 count can be package capacity, not total online CPUs. | B: SMBIOS BIOS/system/baseboard/chassis | GetSystemFirmwareTable(RSMB), bounded type 0/1/2/3 strings, type 0 characteristics, type 1 raw UUID, structure count | I/H/P; firmware configuration through supported VM creation/settings only | Serial formats and marker strings are evidence, not a fabricated physical identity. UUID is raw bytes, not canonical mixed-endian display |
| B/K: firmware consistency | SMBIOS system manufacturer vs Windows BIOS registry mirror | I/H/P; reinstall/repair compatible drivers or Tools only after diagnosing | Mismatch flags an inconsistency, not intent. Cached/overridden registry values need not alter firmware |
| C: BIOS registry | HKLM HARDWARE\DESCRIPTION\System\BIOS values | I/H/P; no edits | Firmware-derived mirrors can be regenerated; editing them would not rewrite SMBIOS |

| C: device enumeration | SetupAPI present PnP hardware IDs, device instance IDs, manufacturer, service, class and driver key | I/H/P; documented host device choices and signed guest drivers | Read-only scan avoids modifying protected Enum keys. | D: Tools processes | ToolHelp process-name inventory retaining heuristic marker matches; registry Run value | I/C/P; remove only saved VMware User Process autostart value | Post-logon check process list and clipboard/drag-drop. Other startup mechanisms may still launch the process |
| D: VGAuthService | SCM/WMI start mode, image path/state, registry Start and DelayedAutoStart preflight | I/C/P; demand-start experiment only, delayed auto-start rejected | Immediate readback then next-boot functional check. Service may start on demand; artifact remains installed |
| D: integration components | vmhgfs, vmxnet, vmci, vmmouse, display/storage drivers visible in SCM/PnP/WMI | I/C/H/P. Optional shared folders/isolation through UI; no automated driver removal | Shared folders, clipboard, guest operations, time sync, shutdown/quiescing, mouse and graphics performance can be affected depending on component |
| E: network | GetAdaptersAddresses GUID/name, description, MAC/OUI, type/status/MTU; WMI PnP/driver association | I/H/C/P; Workstation accepted MAC assignment or network mode manually | VMware OUIs 00:05:69, 00:0C:29, 00:1C:14, 00:50:56 are clues only. Emulated NICs can have non-VMware PCI vendor IDs. Prevent duplicates; preserve DHCP/licensing configuration |
| F: storage | Enumerate disk interfaces; IOCTL_STORAGE_QUERY_PROPERTY vendor/model/revision/serial/bus; WMI IDE/SCSI controllers | I/H/P. Disk size/controller options exist but controller experiments are manual/high risk | Controller changes can prevent boot. Serial strings may be blank, controller-specific or reformatted. No raw writes, ATA vendor commands or identity overrides |
| G: graphics | EnumDisplayDevices identifiers/key/description, EnumDisplaySettings active mode; Win32_VideoController driver/capability fields | I/H/C/P; supported acceleration/monitor settings on host | Disabling 3D changes acceleration, not necessarily adapter identity. Legacy WMI AdapterRAM can truncate large values |
| H: ACPI | Enumerate firmware table signatures, read ACPI headers/OEM IDs/creator/length/checksum | I/H/P/R. Firmware rewriting and passthrough assumptions excluded | Duplicate table signatures return first match through API; no complete AML semantic analysis or physical-memory access |
| I: timing | 101 QPC batches of 64 CPUID(0), 25 Sleep(10) samples with QPC/GetTickCount, raw samples and summary; affinity restored | I/P. No concealment/timer patching | Repeat 5 times under controlled load; CPU power state, VBS, scheduling and suspension confound results. No threshold or VM verdict |
| J: WMI | ComputerSystem/Product, BIOS, BaseBoard, Processor, DiskDrive, IDE/SCSIController, VideoController, NetworkAdapter, PnPEntity, PnPSignedDriver, SystemDriver, Service, OperatingSystem | I; provider and signed driver maintenance when justified | Each class has a timed worker job. No single expected physical-hardware template; mixed vendors are legitimate |

## Research-only exclusions

Kernel patching, SSDT changes, injected DLLs/AppInit hooks, CPUID trapping/masking recipes, firmware rewriting, replacing virtual PCI IDs, deleting hardware enumeration keys, renaming active drivers, hiding processes and anti-tamper bypasses are not implemented. Read-only CPUID/firmware/PnP/SCM measurements expose the relevant layers without those changes.

The toolkit does not inspect every possible surface: no undocumented hypervisor backdoor I/O, TPM attestation, PCI configuration-space writes, full ACPI AML interpretation, application-specific anti-tamper behavior or exhaustive disk firmware protocol pass-through. Timer measurements use documented Windows timers rather than raw RDTSC assumptions. Physical memory size, uptime and small disk size alone are not treated as proof of virtualization.

## API basis

Windows API contracts and minimum supported versions were checked against Microsoft documentation: [firmware](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-getsystemfirmwaretable), [SetupAPI](https://learn.microsoft.com/en-us/windows/win32/api/setupapi/nf-setupapi-setupdigetclassdevsw), [network enumeration](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getadaptersaddresses), [WMI hardware](https://learn.microsoft.com/en-us/windows/win32/wmisdk/wmi-tasks--computer-hardware), [timing guidance](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps). Actual target-machine validation is still required.
